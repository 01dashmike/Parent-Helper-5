## Labels & Accessible Names

### Form Inputs

**Always provide labels for form inputs.** Use one of these methods:

#### Method 1: `<label>` with `htmlFor` (Preferred)

```tsx
<label htmlFor="email-input" className="block text-sm font-medium">
  Email Address
</label>
<input
  id="email-input"
  type="email"
  name="email"
  className="ph-input"
/>
```

#### Method 2: `aria-label` (For icon-only or visually hidden labels)

```tsx
<input
  type="search"
  aria-label="Search for classes"
  placeholder="Search..."
  className="ph-input"
/>
```

#### Method 3: `aria-labelledby` (For complex labels)

```tsx
<div>
  <span id="email-label">Email Address</span>
  <span id="email-required" className="text-red-600">*</span>
</div>
<input
  type="email"
  aria-labelledby="email-label email-required"
  className="ph-input"
/>
```

### Buttons

**All buttons must have accessible names:**

```tsx
// ✅ Good: Text button
<button type="button">Save Search</button>

// ✅ Good: Icon button with aria-label
<button type="button" aria-label="Close dialog">
  <X className="h-4 w-4" aria-hidden="true" />
</button>

// ✅ Good: Button with both text and icon
<button type="button">
  <Search className="h-4 w-4" aria-hidden="true" />
  <span>Search</span>
</button>

// ❌ Bad: Icon-only button without label
<button type="button">
  <X className="h-4 w-4" />
</button>
```

### Links

**Links must have descriptive text:**

```tsx
// ✅ Good: Descriptive link text
<Link href="/search">Search Classes</Link>

// ✅ Good: Icon link with aria-label
<Link href="/account" aria-label="Go to account settings">
  <Settings className="h-4 w-4" aria-hidden="true" />
</Link>

// ✅ Good: Link with visually hidden text
<Link href="/search">
  <Search className="h-4 w-4" aria-hidden="true" />
  <span className="sr-only">Search for classes</span>
</Link>

// ❌ Bad: Link with only icon
<Link href="/search">
  <Search className="h-4 w-4" />
</Link>
```

### Images

**All images must have alt text:**

```tsx
// ✅ Good: Descriptive alt text
<Image
  src="/logo.png"
  alt="Parent Helper logo"
  width={200}
  height={50}
/>

// ✅ Good: Decorative image (empty alt)
<Image
  src="/decoration.png"
  alt=""
  role="presentation"
  width={100}
  height={100}
/>

// ✅ Good: Using safeImage utility
const { src, alt } = safeImage({
  src: classImage,
  alt: `${className} class image`,
});
<Image src={src} alt={alt} width={400} height={300} />

// ❌ Bad: Missing alt
<Image src="/logo.png" width={200} height={50} />
```

### Icons

**Mark decorative icons with `aria-hidden="true"`:**

```tsx
// ✅ Good: Decorative icon
<button type="button" aria-label="Close">
  <X className="h-4 w-4" aria-hidden="true" />
</button>

// ✅ Good: Icon with meaning (no aria-hidden)
<button type="button">
  <AlertCircle className="h-4 w-4" aria-label="Warning" />
  <span>Warning</span>
</button>
```

## Focus Styles

### Standard Focus Pattern

**All interactive elements must have visible focus indicators:**

```tsx
// Standard focus ring pattern
className="focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-sage/50 focus-visible:ring-offset-2"
```

### Implementation Examples

#### Buttons

```tsx
<button
  type="button"
  className="rounded-full bg-sage px-6 py-2 text-white transition hover:bg-sage/90 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-sage/50 focus-visible:ring-offset-2"
>
  Save
</button>
```

#### Inputs

```tsx
<input
  type="text"
  className="ph-input focus-visible:ring-2 focus-visible:ring-sage/40"
  // ph-input already includes: outline-none focus:ring-2 focus:ring-sage/40
/>
```

#### Links

```tsx
<Link
  href="/search"
  className="text-sage hover:text-sage/80 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-sage/50 focus-visible:ring-offset-2 rounded"
>
  Search
</Link>
```

### Focus Ring Specifications

- **Width:** `2px` (ring-2)
- **Color:** `sage/50` or `sage/40` (brand color with opacity)
- **Offset:** `2px` (ring-offset-2) for better visibility
- **Style:** Only visible on keyboard focus (`focus-visible`, not `focus`)

### Custom Focus Styles

For special cases (like map markers):

```css
.leaflet-marker-icon:focus {
  outline: 2px solid #a3b18a;
  outline-offset: 2px;
  filter: hue-rotate(80deg) saturate(1.0) brightness(1.15);
}
```

## Heading Structure

### Rules

1. **One `<h1>` per page** - The main page title
2. **No skipped levels** - Don't jump from `<h1>` to `<h3>`
3. **Semantic hierarchy** - Use headings to structure content, not for styling

### Correct Structure

```tsx
// ✅ Good: Proper heading hierarchy
<article>
  <h1>Class Details</h1>
  <section>
    <h2>Schedule</h2>
    <h3>Weekly Sessions</h3>
  </section>
  <section>
    <h2>Location</h2>
    <h3>Address</h3>
    <h3>Parking</h3>
  </section>
</article>

// ❌ Bad: Skipped heading level
<h1>Class Details</h1>
<h3>Schedule</h3> {/* Should be h2 */}

// ❌ Bad: Multiple h1s
<h1>Class Details</h1>
<h1>Provider Info</h1> {/* Should be h2 */}
```

### Styling Headings

**Use CSS classes for styling, not heading levels:**

```tsx
// ✅ Good: Correct level with styling
<h2 className="text-2xl font-semibold text-charcoal">
  Related Classes
</h2>

// ❌ Bad: Wrong level for styling
<h4 className="text-2xl font-semibold">
  Related Classes {/* Should be h2 or h3 */}
</h4>
```

### Common Patterns

```tsx
// Page title
<h1 className="text-3xl font-bold">Page Title</h1>

// Section headings
<h2 className="text-2xl font-semibold">Section Title</h2>

// Subsection headings
<h3 className="text-lg font-semibold">Subsection Title</h3>
```

## Tap Target Sizes

### Minimum Requirements

**WCAG 2.1 AA requires:**
- **Minimum size:** 44×44 pixels (CSS pixels)
- **Spacing:** At least 8px between targets
- **Mobile priority:** Larger targets on touch devices

### Implementation

#### Buttons

```tsx
// ✅ Good: Minimum 44px height
<button
  type="button"
  className="min-h-[44px] px-4 py-2 rounded-full"
>
  Click Me
</button>

// ✅ Good: Using padding to ensure size
<button
  type="button"
  className="px-5 py-2.5" // py-2.5 = 10px top/bottom = 20px + content = ~44px
>
  Save
</button>
```

#### Icon Buttons

```tsx
// ✅ Good: Icon button with minimum size
<button
  type="button"
  aria-label="Close"
  className="h-11 w-11 flex items-center justify-center" // 44px = 11 * 4px
>
  <X className="h-5 w-5" aria-hidden="true" />
</button>
```

#### Links

```tsx
// ✅ Good: Link with adequate padding
<Link
  href="/search"
  className="inline-block px-4 py-2.5 min-h-[44px]"
>
  Search
</Link>
```

#### Map Markers (Mobile)

```css
/* Mobile touch targets - minimum 44px */
@media (max-width: 768px) {
  .marker-cluster-small div {
    width: 44px !important;
    height: 44px !important;
  }
}
```

### Touch Target Checklist

- [ ] All buttons are at least 44×44px
- [ ] Icon-only buttons have minimum 44×44px container
- [ ] Links have adequate padding (minimum 11px vertical)
- [ ] Spacing between targets is at least 8px
- [ ] Mobile-specific sizes are larger when needed

## Reduced Motion Support

### Media Query

**Always respect `prefers-reduced-motion`:**

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

### Implementation Examples

#### CSS Animations

```css
/* ✅ Good: Respects reduced motion */
.fade-in {
  opacity: 0;
  transform: translateY(8px);
  transition: opacity 0.4s ease, transform 0.4s ease;
}

@media (prefers-reduced-motion: reduce) {
  .fade-in {
    transition: none;
  }
}
```

#### Framer Motion

```tsx
// ✅ Good: Conditional animation
import { motion } from "framer-motion";

const shouldReduceMotion = window.matchMedia("(prefers-reduced-motion: reduce)").matches;

<motion.div
  initial={shouldReduceMotion ? {} : { opacity: 0, y: 20 }}
  animate={shouldReduceMotion ? {} : { opacity: 1, y: 0 }}
  transition={shouldReduceMotion ? {} : { duration: 0.3 }}
>
  Content
</motion.div>
```

#### Leaflet Map Animations

```css
/* ✅ Good: Disable map animations for reduced motion */
@media (prefers-reduced-motion: reduce) {
  .leaflet-marker-icon,
  .marker-cluster div,
  .leaflet-popup,
  .leaflet-tooltip {
    transition: none !important;
    animation: none !important;
  }
}
```

### Best Practices

1. **Disable animations** when `prefers-reduced-motion: reduce`
2. **Keep essential transitions** (like focus states) but make them instant
3. **Test with reduced motion enabled** in browser settings
4. **Use CSS media queries** for automatic detection

## Screen Reader Guidelines

### Semantic HTML

**Use semantic HTML elements:**

```tsx
// ✅ Good: Semantic elements
<nav aria-label="Main navigation">
  <ul>
    <li><Link href="/">Home</Link></li>
    <li><Link href="/search">Search</Link></li>
  </ul>
</nav>

<main>
  <article>
    <h1>Article Title</h1>
    <p>Content...</p>
  </article>
</main>

// ❌ Bad: Div soup
<div>
  <div>Home</div>
  <div>Search</div>
</div>
```

### ARIA Roles

**Use ARIA roles when semantic HTML isn't sufficient:**

```tsx
// ✅ Good: Role for custom component
<div role="search" aria-label="Search for classes">
  <input type="search" />
  <button type="submit">Search</button>
</div>

// ✅ Good: Role for list
<div role="list" aria-label="Search results">
  {results.map(item => (
    <div key={item.id} role="listitem">
      {item.title}
    </div>
  ))}
</div>

// ✅ Good: Role for progress indicator
<div role="progressbar" aria-valuenow={50} aria-valuemin={0} aria-valuemax={100}>
  Loading...
</div>
```

### ARIA States

**Announce dynamic state changes:**

```tsx
// ✅ Good: Expanded state
<button
  type="button"
  aria-expanded={isOpen}
  aria-haspopup="true"
  aria-controls="menu-id"
>
  Menu
</button>
<div id="menu-id" hidden={!isOpen}>
  Menu items
</div>

// ✅ Good: Live regions for updates
<div aria-live="polite" aria-atomic="true">
  {notificationMessage}
</div>
```

### Visually Hidden Text

**Use `sr-only` class for screen-reader-only text:**

The `sr-only` class is provided by Tailwind CSS and visually hides content while keeping it accessible to screen readers.

```tsx
// ✅ Good: Visually hidden but accessible
<button type="button" aria-label="Close dialog">
  <X className="h-4 w-4" aria-hidden="true" />
  <span className="sr-only">Close dialog</span>
</button>

// ✅ Good: Additional context for screen readers
<div>
  <span className="sr-only">Distance: </span>
  <span>2.5 km away</span>
</div>

// ✅ Good: Form description for screen readers
<label htmlFor="search">Search</label>
<p id="search-desc" className="sr-only">
  Enter a town name or postcode to find classes nearby
</p>
<input
  id="search"
  type="text"
  aria-describedby="search-desc"
/>
```

**Note:** `sr-only` is equivalent to:
```css
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border-width: 0;
}
```

### Screen Reader Testing

**Test with actual screen readers:**

1. **NVDA** (Windows, free)
2. **VoiceOver** (macOS/iOS, built-in)

4. **ChromeVox** (Chrome extension)

## Running A11y Tests

### Automated Tests

#### Run All A11y Tests

```bash
# Run Playwright accessibility tests
pnpm run test:a11y

# Or using npm
npm run test:a11y
```

#### Run Specific Test File

```bash
# Run only accessibility tests
npx playwright test tests/a11y/accessibility.spec.ts
```

#### Run with Coverage

```bash
# Run a11y tests with detailed output
npx playwright test tests/a11y/accessibility.spec.ts --reporter=list
```

### Manual Testing

#### Browser DevTools

1. **Chrome DevTools:**
   - Open DevTools (F12)
   - Go to "Lighthouse" tab
   - Run "Accessibility" audit
   - Review violations

2. **Firefox DevTools:**
   - Open DevTools (F12)
   - Go to "Accessibility" tab
   - Review accessibility tree

#### axe DevTools Extension

1. Install [axe DevTools](https://www.deque.com/axe/devtools/) browser extension
2. Open your page
3. Click axe icon in toolbar
4. Review violations

#### Keyboard Navigation Test

1. **Tab through page:**
   - All interactive elements should be reachable
   - Focus should be visible
   - Order should be logical

2. **Test forms:**
   - Tab to each input
   - Verify labels are announced
   - Submit with Enter key

3. **Test navigation:**
   - Tab through menu items
   - Use arrow keys for dropdowns
   - Activate with Enter/Space

### CI/CD Integration

**Tests run automatically in CI:**

```yaml
# .github/workflows/quality-checks.yml
- name: Accessibility Tests
  run: pnpm run test:a11y
```

### Fixing Issues

#### Auto-Fix Common Issues

```bash
# Auto-fix accessibility issues
pnpm run fix:a11y

# Or
npm run fix:a11y
```

#### Manual Fixes

1. Review test output for violations
2. Check axe-core violation descriptions
3. Apply fixes following patterns in this guide
4. Re-run tests to verify

## Quick Reference Checklist

### Before Committing Code

- [ ] All form inputs have labels (`<label>`, `aria-label`, or `aria-labelledby`)
- [ ] All buttons have accessible names (text or `aria-label`)
- [ ] All images have `alt` attributes (descriptive or empty for decorative)
- [ ] All icons have `aria-hidden="true"` when decorative
- [ ] All interactive elements have visible focus styles
- [ ] Heading hierarchy is correct (h1 → h2 → h3, no skips)
- [ ] Tap targets are at least 44×44px
- [ ] Animations respect `prefers-reduced-motion`
- [ ] Semantic HTML is used (`<nav>`, `<main>`, `<article>`, etc.)
- [ ] ARIA attributes are used correctly (when needed)
- [ ] Keyboard navigation works (Tab, Enter, Space, Arrow keys)

### Component Checklist

```tsx
// ✅ Complete accessible component example
<button
  type="button"
  aria-label="Save search"
  className="min-h-[44px] px-4 py-2 rounded-full bg-sage text-white hover:bg-sage/90 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-sage/50 focus-visible:ring-offset-2"
  onClick={handleSave}
>
  <Save className="h-4 w-4" aria-hidden="true" />
  <span>Save</span>
</button>
```

### Common Patterns

#### Accessible Form

```tsx
<form onSubmit={handleSubmit}>
  <label htmlFor="email" className="block text-sm font-medium">
    Email Address
  </label>
  <input
    id="email"
    type="email"
    name="email"
    required
    aria-describedby="email-error"
    className="ph-input focus-visible:ring-2 focus-visible:ring-sage/40"
  />
  <div id="email-error" role="alert" aria-live="polite">
    {errors.email}
  </div>
  <button
    type="submit"
    className="ph-btn min-h-[44px] focus-visible:ring-2 focus-visible:ring-sage/50"
  >
    Submit
  </button>
</form>
```

#### Accessible Navigation

```tsx
<nav aria-label="Main navigation">
  <ul className="flex gap-4">
    <li>
      <Link
        href="/"
        className="px-4 py-2.5 focus-visible:ring-2 focus-visible:ring-sage/50"
      >
        Home
      </Link>
    </li>
    <li>
      <Link
        href="/search"
        className="px-4 py-2.5 focus-visible:ring-2 focus-visible:ring-sage/50"
      >
        Search
      </Link>
    </li>
  </ul>
</nav>
```

#### Accessible Modal

```tsx
<div
  role="dialog"
  aria-modal="true"
  aria-labelledby="modal-title"
  aria-describedby="modal-description"
>
  <h2 id="modal-title">Confirm Action</h2>
  <p id="modal-description">Are you sure you want to proceed?</p>
  <button
    type="button"
    aria-label="Close dialog"
    onClick={onClose}
  >
    <X className="h-4 w-4" aria-hidden="true" />
  </button>
</div>
```

## Questions?

If you're unsure about an accessibility pattern:

1. **Check this guide first**
2. **Run `pnpm run test:a11y`** to see if it passes
3. **Test with keyboard navigation** (Tab through the page)
4. **Check with axe DevTools** extension
5. **Ask the team** or refer to WCAG 2.1 guidelines

**Remember:** Accessibility is not optional. Every user deserves equal access to our application.
